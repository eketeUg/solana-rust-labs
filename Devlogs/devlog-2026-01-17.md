Technical deep-dive / most interesting thing I learned

The key lesson today was understanding that Anchor does not rely on my system Rust installation when building programs.

Even though I already had rustc and cargo installed and working, anchor build failed with an error like:

error: not a directory: '/Users/ekete/.local/share/solana/install/releases/stable-edda5bc036f8157e28d314afefe0cb4656f7cd94/solana-release/bin/platform-tools-sdk/sbf/dependencies/platform-tools/rust/lib'

At first this was confusing, because from a normal Rust perspective, everything was set up correctly.

What I learned is that Solana programs are compiled to SBF, and Solana maintains its own embedded Rust toolchain and sysroot inside the Solana installation. Anchor simply delegates to that toolchain.

So the real issue was not Rust itself, but the fact that Solana’s SBF platform tools were either incomplete or corrupted. Anchor was looking for:

platform-tools/rust/lib

and it didn’t exist as a valid directory.

The fix was to explicitly force Solana to reinstall its SBF toolchain:

```bash
cargo build-sbf --force-tools-install
```

This command rebuilt the entire SBF environment, recreated the missing Rust sysroot, and immediately unblocked anchor build.

Key takeaway

When working with Solana + Anchor, toolchain issues are usually Solana-SBF related, not Rust-related. If Anchor fails with missing platform-tools or rust/lib errors, forcing a fresh SBF tools install is often the correct and fastest solution.

- Deployment got stuck at finalizing transaction...
- Diagnosed that the local validator state was likely corrupted or had pending transactions
- Restarted the validator using:

```bash
solana-test-validator -r
```

    After restarting, deployment worked successfully

Technical deep-dive / most interesting thing I learned

Anchor’s localnet deployment can hang if the local validator has a stuck state or pending transactions. Even when the program build is fine, Anchor waits for the transaction to finalize. Restarting the validator with --reset clears the ledger and validator state, allowing the deployment to proceed normally.

This reinforced the workflow of running the validator manually and using --skip-local-validator during repeated builds for faster iteration.

Key takeaway
• If localnet deployment hangs at finalizing transactions, always try:

```bash
solana-test-validator -r
```

    •	Keep the validator running manually for faster iteration and avoid unnecessary restarts during development.
